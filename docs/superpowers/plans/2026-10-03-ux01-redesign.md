## Global Constraints

- Selected reference: [option 1](../../design/ux01-owner-home-option1.png); owner Home/Customers/More, customer My QR/My shops/More. No wallet/premium/khata alternative substitution.
- Colors: canvas/surface `#FFFFFF`, muted `#F8FAF9`, primary `#14532D`, onPrimary `#FFFFFF`, tint `#EAF4ED`, text `#111827`, secondary `#475569`, outline `#64748B`, divider `#E2E8E4`, credit `#9A3412`, payment `#166534`, Pending `#92400E`/`#FFF4D6`, attention `#B91C1C`/`#FEF2F2`.
- Type: page/brand 24/700; primary balance 32/700 (36 only wider); section 20/700; row/action 16/600; body/field 16/400; metadata 14/400–600. Android system sans/Devanagari fallback; no new font download/package.
- Spacing 4/8/12/16/24/32; compact outer 16, wider 24; card/row padding 16; card radius 16; input/action radius 12; decorative initials 40–48. Targets ≥48×48 logical pixels; filled actions ≥56 high and expandable.
- Verify 320 logical pixels and 200% text, keyboard, SafeArea and landscape. Never ellipsize money or disable scaling. Contrast targets 4.5:1 normal text, 3:1 large text/meaningful graphics; status uses text/icon/color.
- Preserve one owner shop, customer multiple shops, integer paise/current limits, immutable history, durable account-isolated outbox, original operation/body retry, review before save, QR lookup-only, online first link and manually recorded Cash/UPI.
- Home total is existing acknowledged server summary only; do not sum pages/local balances. Pending counts separate; unavailable total is not zero. Per-link provisional value uses existing snapshot calculation; customer/statement data acknowledged only.
- Preserve snapshot/partial-refresh distinctions; due-summary 60-second expiry/eligibility; authorization/cache-clear/account-generation guards; denied content never gets stale fallback.
- Keep scanner → customer workspace → credit/payment. Existing deep links remain valid; no implicit link/post/rotate/remove/share on Back.
- No backend/schema/repository/accounting/sync interfaces changed; no new dependencies, real data, remote changes or publication from this plan. D22–D24 and unperformed D21/policy/backup gates remain unchanged.
- Preserve existing native date/share/camera lifecycle, sign-out Pending safeguards, data-request test policy and relink limitation. All copy/semantics English/Hindi via current resources: update `udhaarkhata/l10n/app_en.arb`, `udhaarkhata/l10n/app_hi.arb` and `udhaarkhata/lib/app/app_strings.dart` together, preserving key/placeholder equality; every copy-changing task inherits these exact file assignments. No per-widget hardcoded translated strings.

New shared files under `udhaarkhata/lib/app/ui/`:
- `money_format.dart`: `String formatDisplayPaise(int value)` groups the integer rupee part using Indian groups (last 3 digits, preceding groups of 2), prefixes `-` before ₹ for negative values, and always renders exactly 2 paise digits from integer remainder; no float conversion.
- `app_tokens.dart`: `abstract final class AppTokens` static color/spacing/radius constants and `ThemeData clearCounterTheme()`.
- `task_scaffold.dart`: `TaskScaffold({required String title, required Widget child, List<Widget> actions = const []})`; scroll/insets remain owned by caller, no nested scroll surprise.
- `identity_panel.dart`: `IdentityPanel({required String displayName, String? nickname})`.
- `balance_panel.dart`: `enum BalanceSource { confirmed, provisional }`; `BalancePanel({required int amountPaise, required String directionLabel, required BalanceSource source, int? syncedPaise, required int snapshotAtMs, int? partialSyncAtMs, bool offline = false})`.
- `state_panel.dart`: `StatePanel({required String title, required String message, bool loading = false, String? actionLabel, VoidCallback? onAction})`.
- `status_chip.dart`: `enum EntryDisplayStatus { synced, pending, attention }`; `StatusChip({required EntryDisplayStatus status})`; Pending explanatory copy is also mandatory on enclosing financial view.
- `ledger_row.dart`: `LedgerRow({required String typeLabel, required int effectPaise, required int occurredAtMs, required EntryDisplayStatus status, required Widget details})`; disclosure state is UI-only.
- `financial_panels.dart`: `FinancialReview({required String customerName, required String actionLabel, required int amountPaise, required List<Widget> details, required bool busy, required VoidCallback onSubmit, VoidCallback? onEdit})`; `SaveReceipt({required String title, required int amountPaise, required bool pending, required List<Widget> details, required VoidCallback onReturn})`.

Source-specific adapters remain in feature presentation files; balance widgets receive repository values, not compute new money. Source import locations: `CachedOwnerLedger` in `core/db/ledger_dao.dart`; `OnlineReadPage`/`ShopLedger` in `features/ledger/online_reads.dart`; `HistoryEntry` in `core/network/ledger_entry.dart` (also exported by online_reads); `CustomerLink` in `features/qr/owner_qr_model.dart`; attempts/receipt in `features/ledger/entry_model.dart`; `Dispute` in `features/disputes/dispute_repository.dart`; `QrView` in `features/qr/qr_model.dart`; `Shop` in `features/shop/shop_repository.dart`; `AccountRole` in `core/auth/account.dart`. `OnlineReadPage.records` remains `List<Object>`; use existing checked switch patterns rather than unchecked list casts.

New `features/disputes/dispute_entry_context.dart` defines immutable `DisputeEntryContext({required String accountId, required String shopId, required String entryId, required String kind, required int amountPaise, required int occurredAtMs})` with `bool matches({required String accountId, required String shopId, required String entryId})`. Router accepts optional `state.extra is DisputeEntryContext`, and consumers validate scope/current account each render. It is not persisted or used for permissions/API bodies.

Existing `OnlineRecordsView` gains UI-only optional named parameters `int? previewLimit` and `bool showControls = true`; default behavior stays unchanged. Home uses limit 3/control suppression, full Customers uses defaults. Preview never changes loaded cursor/order, endpoints or complete-history verification. Existing `SyncStatusView` consumes `SyncRunState` from `lib/core/sync/coordinator.dart` (`pendingCount`, `needsAttentionCount`, `lastSuccessfulAtMs`, `running`, `errorCode`) and gains `bool compact = false` and `VoidCallback? onOpenDetails`; compact strips delegate to full existing detail logic rather than new sync state.
