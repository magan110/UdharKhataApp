**Goal:** Implement remaining first-release features through D21 and deliver one staging APK for user phone testing.
**Architecture:** Existing Worker/D1 authoritative immutable ledger, account-isolated Flutter SQLite outbox, additive feature modules, explicit share and tracked privacy controls.
**Tech stack:** Flutter/Dart, Cloudflare Worker/D1, Zod, Vitest, SQLite.
**Spec:** [D13–D21 design](../specs/2026-10-02-d13-d21-design.md).

## Global constraints

Integer paise; prepared SQL; current authorization before replay; stable operation IDs; no erased history or Pending loss; no automated outgoing messages; no sensitive telemetry; synthetic data only. User authorized continuous execution and final staging test APK, so phase approval pauses are unnecessary.

## Review focus

| Failure class | Owner | Evidence |
|---|---|---|
| Correction duplicate/stale/concurrent balance mutation | Financial server + ledger UI | D1/SQLite receipt and revision tests |
| Foreign dispute/privacy/removed relationship access | Trust server | Route authorization matrix and balance equality |
| Offline QR/customer cache cross-account leak | Offline QR | Known/unknown/revoked/cache isolation tests |
| Export mismatch/injection/Hindi text loss | Sharing/localization | Reconciliation, formula sentinel and font tests |
| Quota loss/telemetry leakage/restore corruption | Root | Retry/redaction/rate limit/isolated restore/full regression |
