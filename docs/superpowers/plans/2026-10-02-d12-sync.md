> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reconcile durable owner credit/payment exactly once after reconnect, support offline restart for a previously verified account, and prevent cross-session cache access.

**Architecture:** Retain the financial POST and receipt hash, add a scoped incremental feed, and apply acknowledgements/pages transactionally to existing SQLite. A generation-bound coordinator serializes push/pull and schedules bounded retries. A secure-storage local grant permits offline access without granting cloud authorization.

**Tech Stack:** Existing Flutter/Dart, Riverpod, sqflite, flutter_secure_storage, http; TypeScript Worker, D1, Vitest and native SQLite FFI tests. No new dependency is planned.

**Spec:** [Approved D12 design](../specs/2026-10-02-d12-sync-design.md), approved by the user on 2 October 2026. This plan awaits review and execution-method selection.

## Global Constraints

- Android-first, INR integer paise; preserve immutable original payloads, operation IDs and existing receipt hashes.
- One run per account/shop; at most 20 commands and 20 pull pages per run; requests sequential; repeated triggers coalesce.
- Pull default 50, maximum 100 entries; fixed high-water, account/role/route/shop/link-bound authenticated cursor with existing one-hour expiry.
- Backoff starts at 2 seconds, doubles to a maximum base of 5 minutes; jitter between half and full base. Valid Retry-After is a minimum even above the cap.
- Local access expires 30 days after online verification; offline use cannot renew it. Uncertain refresh requires online reauthentication and locks the cache.
- First credit/payment occurrence time accepts nonnegative safe integers through server now plus 5 minutes; no lower age restriction. Server sequence/commit time controls posting order.
- Preserve the 10,000-entry automatic-cache limit, large-ledger server-history fallback, legacy Check same command recovery and account-private backup exclusions.
- Pending is device-only; Needs attention retains original command and is excluded from Synced/Pending sums. Never silently edit, discard or replace a financial command.
- Use synthetic data only. Local commits are allowed; no push, deploy, publication, real-data action or remote configuration without explicit approval.

## Review Focus

- A same-account reopen races with a late response: the old generation cannot apply it (Tasks 3 and 4).
- A push acknowledgement is ahead of unpulled other-device entries: no cursor leap or incomplete snapshot claim (Tasks 3 and 6).
- A malformed gateway error contains a long Retry-After: retain HTTP status and defer without early retries (Task 1).
- D11 rows without operation identity later receive it: attach once only after all immutable fields match (Task 3).
- A backwards device clock or capped customer list hides stale authorization: grants fail closed on future verification time and every cached link is reauthorized individually (Tasks 4 and 6).
