User authorization: complete D13 through D21 continuously and deliver a final APK. Implementation, existing synthetic staging deployment and test artifact are authorized. No production deployment, real customer data, destructive deletion or legal-policy approval is implied.

## Contracts and invariants

Existing UUID receipts, account-isolated durable outbox, prepared SQL and immutable posted history remain authoritative. Offline repeat QR uses only verified active account/shop mappings; unknown QR cannot create relationships. Customers cache acknowledged snapshots only, with dated offline labels. Replacement phones recover server-acknowledged records only; Android backup remains disabled.

Correction commands append an immutable entry with original ID, nonnegative target amount, expected revision and reason. The effect is the difference from the effective original credit/payment. Live SQL guards prohibit stale revision, cross-tenant mutation and negative authoritative balance. Credit/payment canonical hashes stay compatible. Rejected local corrections retain original payload as Needs attention.

Due allocation uses corrected effective credits and payments. Credits sort by due date (undated last), server sequence then ID. Calendar due dates have no timezone; overdue means due date strictly earlier than selected calendar date. Complete server summaries preserve signed entry sums.

Disputes require current customer access to their own acknowledged entry, one open dispute per entry and a reason. Only the owning shop resolves with a note; neither action changes money. Privacy requests are tracked, scoped and authenticated. Access removal revokes the relationship while preserving owner history. Relink remains blocked pending published privacy policy; destructive deletion is deferred.

Statements reconcile opening, ordered immutable effects and closing from a complete authorized snapshot, with bounded periods and size. Pending entries never contribute to cloud totals. CSV injection is neutralized; PDFs bundle licensed Hindi-capable fonts. Reminders and files require an explicit reviewed native share action. English/Hindi localization is persisted; human Hindi/TalkBack/device checks remain pending final phone testing.

Safe telemetry uses route templates, errors, status and latency; no names, amounts, notes, tokens, subjects or QR IDs. Rate limits use authenticated principals for write routes and bounded shared-network auth protection. A synthetic encrypted restore drill proves ledger sums, identities and receipts in isolation. Real backup setup, named operators and reviewed retention remain public-use gates.

## Ownership and review

Independent agents own financial server, trust server, offline QR/customer cache, correction/dispute/due Flutter, and sharing/localization. Root owns router/settings integration, runtime limits/telemetry, documentation, restore verification and delivery. No agent commits shared changes. Root reviews interfaces and runs all suites before staging deployment and APK delivery.

## Delivery truthfulness

D13–D20 implementation evidence and D21 automated results are recorded individually. Device testing, Hindi-speaker review, real backup infrastructure and reviewed policy are explicitly pending where evidence is unavailable. A private-test APK is a candidate, not approval for public launch. D22–D24 remain outside scope.
